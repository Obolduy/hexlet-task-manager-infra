# AGENTS.md

Правила для агента в этом репозитории (`review-action/`, `knowledge-service/`).

## Стек

Python 3.11. FastAPI для HTTP-сервисов, `psycopg2` + `pgvector` для доступа
к Postgres, `sentence-transformers` для эмбеддингов, `mcp` (FastMCP) для
MCP-серверов.

## Комментарии

Не писать комментарии по поводу и без. Комментарий оправдан, только когда
объясняет **почему**, а не **что**: скрытое ограничение, неочевидный
инвариант, обход конкретного бага. Если комментарий пересказывает то, что
уже понятно из названия переменной, функции или колонки — не писать его,
а если он уже есть — удалить.

Не писать многострочные докстринги и блоки-пересказы кода. Одна строка
на функцию/модуль — максимум, и только если без неё читатель ошибётся.

Плохо: `# получаем эмбеддинг` над строкой `model.encode(...)`.
Хорошо: `# должна совпадать с EMBEDDING_MODEL в .env` рядом с
`vector(384)` — без этого комментария непонятно, откуда взялось число.

## Общие принципы

- Импeратив и конкретика вместо общих слов: «эндпоинты в `server.py`,
  логика поиска — в SQL» вместо «пиши аккуратно».
- Не класть в код бизнес-документацию и объяснения архитектуры — для
  этого есть `webinar-implementation-plan.md` и PR-описания.
- Строка подключения к БД — только из переменной окружения, констант
  с адресами/паролями в коде быть не должно.
- Один файл — одна точка ответственности. `server.py` и `mcp_server.py`
  должны читаться за минуту на экране — это требование демо.
- Не изобретать инфраструктуру сверх задачи (пулы соединений, ретраи,
  кэши) без явного запроса — это демо-репозиторий, а не прод-сервис.

## Формат PR

Коротко: что изменилось и зачем. Без раздела «как проверить», если
это очевидно из diff.
