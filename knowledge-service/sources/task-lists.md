# Соглашения по спискам и выборкам задач

Во всех интерфейсах, где команда работает со списком задач — общий список, персональный экран участника, сравнение нагрузки между людьми — состав списка формируется по одним и тем же правилам. Этот документ описывает, что попадает в список по умолчанию и как список ведёт себя при уточнении.

## Какие задачи попадают в список по умолчанию

По умолчанию список показывает то, с чем команде нужно работать прямо сейчас: задачи в общем пуле, задачи в работе и задачи на проверке. Завершённая работа в список по умолчанию не входит — такие задачи не показываются, пока человек явно не попросит их увидеть, например переключившись на историю или архив. Причина простая: список по умолчанию — это рабочая поверхность на сегодня, и держать в ней уже закрытые задачи означало бы постоянно засорять то, на что команда смотрит каждый день.

## Как общий пул отображается при уточнении по участникам

Когда список сужают до конкретного участника или сравнивают нагрузку нескольких человек, задачи без назначенного исполнителя нельзя просто убирать из вида. Они принадлежат не одному человеку, а команде целиком, поэтому при уточнении по участнику общий пул должен оставаться видимым отдельно — как часть общей картины, а не как что-то, что отсеялось вместе с задачами других людей. Если убрать пул из вида при таком уточнении, команда потеряет из виду задачи, которые как раз и нужно кому-то забрать.

## Как формируются списки на разных экранах

Общий экран команды объединяет пул и активную работу всех участников. Персональный экран участника показывает его собственные задачи и отдельно — общий пул, чтобы человек мог видеть, что доступно взять в работу. Экран сравнения нагрузки строится так же: суммирует активную работу по каждому участнику и отдельной строкой показывает то, что ещё никто не взял.

## Что делать, если список выглядит пустым или неполным

Если персональный список участника пуст, это не всегда значит, что для команды нет работы — стоит проверить общий пул, в нём может быть достаточно задач для старта. И наоборот: если в общем списке команды не видно уже сделанной работы, это ожидаемо — переключитесь на показ истории, чтобы её найти.
