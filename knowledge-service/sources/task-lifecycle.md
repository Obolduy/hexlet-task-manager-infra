# Жизненный цикл задачи

Трекер задач сопровождает работу команды от постановки задачи до её закрытия. У каждой задачи есть текущая стадия, и переход между стадиями отражает реальное событие в работе, а не техническую отметку.

## Какие стадии проходит задача

Задача создаётся, когда работа поставлена и описана. Дальше она либо сразу передаётся конкретному участнику, либо остаётся без назначенного исполнителя и попадает в общий пул команды — общий список задач, доступных любому участнику. Из пула или сразу после постановки задача переходит в работу, когда кто-то берёт её на себя. После того как работа сделана, задача уходит на проверку. Проверка заканчивается либо возвратом в работу с замечаниями, либо переводом задачи в завершённые. Отдельно предусмотрена отмена — для задач, которые перестали быть нужны ещё до того, как по ним начали работать.

## Что происходит с задачей без исполнителя

Не у каждой задачи в момент постановки есть человек, который будет её делать. Если при создании исполнитель не указан, задача не зависает в неопределённом состоянии — она попадает в общий пул команды и остаётся там до тех пор, пока кто-то из участников не возьмёт её в работу самостоятельно.

Это нормальная, ожидаемая стадия жизненного цикла, а не признак того, что данные заполнены не полностью или задачу забыли кому-то передать. Команда сознательно работает по модели, где часть задач лежит в общем доступе: так участники сами разбирают работу по мере освобождения, а лид не превращается в единственную точку, через которую обязательно проходит каждое назначение. Если бы отсутствие исполнителя считалось ошибкой, любая задача из пула требовала бы немедленного вмешательства — а на практике команда держит в пуле по несколько задач постоянно, и это работает.

## Кто переводит задачу между стадиями

Взять задачу из общего пула в работу может любой участник команды — для этого не нужно разрешение лида. А вот перевод задачи на проверку и её закрытие — это уже действие того, кто ведёт проверку: обычно лид направления или назначенный ревьюер. Отмена задачи доступна тому, кто её поставил, либо лиду.

## Что означает завершение задачи

Задача считается завершённой только после того, как прошла проверку и получила подтверждение, что сделана верно. Перескочить проверку и закрыть задачу напрямую нельзя — так команда договорилась защищаться от ситуаций, когда работа выглядит готовой, но на деле содержит недоделки. Как только задача закрыта, она считается полностью сделанной: команде больше не нужно держать её в поле внимания, возвращаться к ней или отслеживать её ход — работа по ней окончена.
